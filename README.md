# College Schedule

React + TypeScript + Vite: демонстрационный интерфейс расписания колледжа.

Исходники интерфейса публикуются в этом репозитории. В демонстрации данные сохраняются локально в браузере; подключения к production College Ecosystem нет.

Развёртывание: GitHub Actions → GitHub Pages.

## Проверка замен и массового изменения формата

- Каждая замена сначала проходит проверку, потом отдельное подтверждение. Планирование учитывает окна группы и нового преподавателя, включая нормативное время на дорогу между очным и дистанционным занятием.
- Неделя всегда указана с точными датами; мини-расписание отображает шесть возможных пар. Массовое изменение формата поддерживает одну группу, отделение или все группы с проверкой каждого занятия, включая потоки, КУГ и ограничения; при ошибке изменение не применяется без просмотра результатов.

## Замены: другой предмет или дистанционное занятие

- У колледжа есть своя стратегия замещения: **другой предмет** (по умолчанию), комбинированная или только **другой преподаватель**. Варианты из текущего демо Academic Core относятся только к утверждённым *демо*-назначениям конкретной группы, с доступным преподавателем, подходящим свободным кабинетом и проверкой учебного календаря.
- Дистанционная замена — синхронное занятие другого доступного преподавателя, а не объявление заболевшего преподавателя работающим онлайн. По умолчанию максимум **20% дистанционных занятий за учебную неделю**, **одна онлайн-пара в день**, онлайн-пары располагаются **только с края** расписания и имеют минимум **одну свободную пару на дорогу** между дистантом и очным обучением для группы и преподавателя. Правила можно ужесточать в интерфейсе; нарушения не предлагаются.
- Замены применяются **по одной с подтверждением**, учитывают все преподавательские и аудиторные конфликты и не трогают проведённые занятия. Журнал хранит исходную и новую дисциплины, преподавателя и формат; отмена восстанавливает исходные значения. Недополученные часы исходного предмета отмечаются как требующие перепланирования. Реальный учёт часов, согласование и уведомления должны быть интегрированы с Academic Core и RBAC.
 
## Годовой планировщик и перетаскивание

- УП, ПП и ПДП автоматически считываются из календарного учебного графика (КУГ) каждой группы по фактическим рабочим дням, включая смешанные недели. Ручная вкладка «Практика» удалена, старые сохранённые блоки игнорируются без сброса остальных настроек.
- КУГ определяет периоды; Academic Core должен давать назначения, руководителей, места и нагрузку. Пока интеграции нет, расчёт показывает конкретные незаполненные назначения, не придумывает кабинеты, руководителей или учебные часы; обычные занятия в дни практики не создаются.
- После перетаскивания занятия левой кнопкой мыши панель свойств не открывается; при успешном drop остаётся диалог подтверждения. Обычный щелчок и контекстное меню сохранены.

## Производственный календарь и обновления

- Единые правила `src/productionCalendar.ts` используются КУГ, недельным расписанием, проверкой переносов и годовым планировщиком (включая worker). Поддерживаются федеральные праздники, пять или шесть учебных дней, выходные по переносам и сокращённые предпраздничные дни. Учебные периоды групп хранятся отдельно: государственный праздник не заменяет тип учебной недели.
- `scripts/sync-production-calendar.py` получает данные для пяти- и шестидневки от **справочного**, не нормативного сервиса [isdayoff.ru](https://isdayoff.ru/). Скрипт проверяет длину года, все воскресенья, допустимые коды и подтверждённые постановления Правительства РФ № 1466 (2026) и № 1187 (2027). Если справочный API противоречит постановлению, встроенные нормативные данные имеют приоритет, а расхождение записывается в `warnings`.
- `.github/workflows/sync-production-calendar.yml` выполняет проверку **ежедневно** и вручную из GitHub Actions. После валидации два календарных JSON сохраняются в `main` безопасным способом (повторная выборка актуальной ветки, новый коммит и ограниченные повторы при изменении ветки), включаются в GitHub Pages и сохраняются как артефакт запуска GitHub Actions (90 дней). Это позволяет сохранять проверяемую историю без конфликтного `git rebase`. Если источник недоступен, сайт продолжает работать по встроенному календарю, ошибки фиксируются в Actions.
- Браузер получает опубликованный файл при запуске, а долгоживущая вкладка периодически проверяет обновление. КУГ, расписание и автосоставление используют один набор правил; календарь передаётся в worker при расчёте годового плана. **Запланированные и проведённые занятия не переносятся и не удаляются автоматически.** Затронутые пары отмечаются как требующие проверки; устаревшие варианты годового расчёта нельзя применять без пересчёта.
- Для годов, на которые ещё не опубликовано подтверждённое постановление о переносах, статусы из внешнего источника считаются **предварительными**. Дополнительные региональные или внутренние нерабочие дни оформляются отдельно в КУГ; новая организация должна настраивать их через свои права, не изменяя общие федеральные правила.

Сейчас это статический демонстрационный стенд GitHub Pages, а не production-интеграция Academic Core. При переносе в единый NestJS-монолит источником состояния станет серверный модуль, с аудитом изменений, уведомлениями и проверками scope/RBAC.

### Нормативные уведомления и ручные решения учебной части

- `scripts/monitor-official-calendar.py` ежедневно **пытается** проверить опубликованные документы на `publication.pravo.gov.ru`. Это мониторинг заголовков и кандидатов для ручной правовой проверки, а **не автоматическое толкование** новых законов. Отказ портала отображается как `unavailable`, неполная проверка — `partial`. Нельзя считать результат юридически подтверждённым, если источник недоступен.
- `scripts/sync-production-calendar.py` дополняет общие данные объяснениями расхождений, режимом пяти-/шестидневки и ссылками на акт. `scripts/notify-calendar-admin.py` формирует одну обновляемую [задачу GitHub Issues](https://github.com/AlexeyParfenov12/college-schedule/issues) без повторной отправки одинаковых предупреждений. Это уведомление подписчикам **репозитория**, а не персональная доставка сотруднику колледжа.
- Для адресного письма учебной части нужно настроить GitHub Actions Secrets: `ACADEMIC_ADMIN_EMAIL`, `CALENDAR_SMTP_HOST`, `CALENDAR_SMTP_FROM`, при необходимости `CALENDAR_SMTP_PORT` (по умолчанию 465), `CALENDAR_SMTP_USERNAME`, `CALENDAR_SMTP_PASSWORD`. Без этих секретов отправка email **отключена**. Почтовый шлюз может подтвердить приём письма, но не факт прочтения.
- В «Учебном календаре» встроен «Центр календаря учебной части»: конкретная дата, объяснение отличия API и применённого правила, ссылка на официальную публикацию; новые потенциально значимые акты требуют проверки полного текста. Источник может быть временно недоступен.
- Редактор «Ручное изменение дней колледжа» добавляет **локальные** дополнительный выходной/праздник, рабочую субботу или сокращённый день с датой и основанием. Сначала показывается число затронутых занятий; данные сохраняются в `college-production-overrides-v1` текущего браузера и участвуют в ручном расписании, КУГ, валидации и worker-расчёте. Дополнительный рабочий день не может отменить федеральный праздник и подтверждённый перенос. Сокращённый день сейчас меняет календарный статус, а не продолжительность каждой пары.
- Автор, RBAC, approval flow, серверный аудит и синхронизация ручных решений между устройствами **не реализованы** в статическом прототипе. Они должны использовать единый Auth/RBAC/Notifications Academic Core при интеграции, без создания параллельных локальных учётных записей.

**Важно для эксплуатации:** официальный портал иногда недоступен из GitHub Actions. При `unavailable` или `partial` новый нормативный документ не считается обнаруженным или отсутствующим достоверно. Изменения, требующие юридического толкования, остаются задачами учебной части с указанным источником. Уведомления в виде GitHub Issue доступны подписчикам репозитория; персональный email не отправляется, пока секреты доставки не настроены.

## Импорт календарного учебного графика через шаблон Excel/CSV

В разделе **«Учебный календарь» → «Шаблон таблицы, импорт и экспорт»** можно скачать пустой CSV-шаблон для выбранного учебного года (все известные группы и 53/52 недели с точными датами), заполнить его в Excel и загрузить обратно. Шаблон использует UTF-8 с BOM, разделитель `;`, точные заголовки недель. Заголовки и идентификаторы групп не менять.

**Коды периодов:** `Т` — теория, `УП` — учебная практика, `ПП` — производственная практика, `ПДП` — преддипломная практика, `ПА` — промежуточная аттестация, `ГИА` — государственная итоговая аттестация, `К` — каникулы, `ИН` — иной период, `—` — намеренно не заполнять эту неделю. **Пустые ячейки не изменяют данные**. Для нескольких разных периодов внутри недели допускается ровно семь кодов через `|`, от понедельника до воскресенья; пустой код дня также оставляет его неизменным. Дни за пределами учебного года отмечаются `~`.

После загрузки выполняется проверка структуры, выбранного года, существующих групп и кодов периодов. До сохранения показывается количество изменяемых групп, недельных ячеек и периодов. Импорт не затрагивает пустые ячейки, соседние группы и другие учебные годы. Уже созданные занятия автоматически не удаляются и не переносятся — их нужно проверить после импорта. Для редактирования *всего* текущего графика есть отдельная кнопка **«Скачать текущий график CSV»**.

Шаблон относится к демонстрационному фронтенду GitHub Pages; в общей экосистеме хранение изменений и согласование с учебной частью должны осуществляться через серверный Academic Core и аудит.
