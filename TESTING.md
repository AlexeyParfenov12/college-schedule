# College Schedule — интерактивный стенд функциональности

**Сайт:** https://alexeyparfenov12.github.io/college-schedule/

Это самостоятельный прототип College Schedule на React + TypeScript + Vite, визуально согласованный с College Ecosystem. Он предназначен для проверки UX, академической модели и бизнес-правил **на синтетических данных**, без подключения к рабочему колледжу.

## Набор демонстрационных данных

- 36 академических групп из 4 отделений, 72 преподавателя, 56 аудиторий;
- 27 дисциплин, 16 учебных недель, 6 дней/неделю, до 6 пар в день;
- список студентов каждой группы с распределением на подгруппы;
- подгруппы практических занятий, поточные лекции, параллели, очный и дистанционный форматы;
- период практики, каникулы, сессии и образцы отсутствий преподавателей.

Данные не содержат реальных персональных сведений. Изменения сохраняются **только в браузере** в виде отклонений от исходной базы, чтобы не переполнять localStorage тысячами одинаковых записей. Полный сброс — внизу интерфейса: **Сбросить демоданные**.

## Основные ограничения стенда

Это **не production-версия College Ecosystem**: нет NestJS API, PostgreSQL, ролей и реальной авторизации, подтверждения часов электронным журналом, видеоконференций, уведомлений, файлового хранилища и государственной отчётности. Прототип показывает, как эти процессы будут выглядеть, и позволяет проверять существенную часть бизнес-правил локально.

Функции автосоставления — демонстрационная эвристика поиска допустимых свободных слотов, а **не промышленный математический решатель всех ограничений**. Учебные часы, отметки проведения и версии являются тестовыми записями. Официальные данные должны приходить из согласованных моделей Academic Core и College Space.

## Проверка через GitHub Actions

Каждый push в `main` запускает:
1. `npm install --no-audit --no-fund`;
2. `npm test` — тесты ограничений расписания;
3. `npm run build` — TypeScript и Vite;
4. публикацию через GitHub Pages.

Для запуска локально:

```bash
npm install
npm run dev
npm test
npm run build
```

Конфигурация публикации находится в `.github/workflows/pages.yml`.

## Архитектурная совместимость

При интеграции в основной модульный монолит база и API живут в NestJS + Prisma + PostgreSQL, фоновые задачи — Redis/BullMQ, файлы — College Cloud/S3. Группы, студенты, преподаватели, назначения нагрузки и учебные планы — из Academic Core. Занятия связываются с общей моделью `Lesson`, а оценки, посещаемость и фактическое проведение часов — с электронным журналом. Дублировать авторизацию или академические справочники в College Schedule не нужно.


## Обновление UX — компактная диспетчерская работа

После запуска новой версии проверь следующие сценарии:

1. **Подсветка переноса.** Открой «Расписание», группу П-21 и нажми на существующую пару. Сетка переходит в режим выбора. Зелёные ячейки разрешены, красные запрещены; наведение показывает причину. Выбери зелёную ячейку, изучи предварительный просмотр «Было → Стало» и подтверди. Пары потока или параллели переносятся как единое занятие со всеми участниками.
2. **Отмена действия.** После переноса нажми «Отменить» в верхней панели либо `Ctrl+Z` вне текстового поля. Восстановится предыдущая позиция.
3. **Умные рекомендации.** Выбери занятие: справа открывается помощник с альтернативными временными слотами, свободными квалифицированными преподавателями, доступными аудиториями и безопасными обменами. Выбор преподавателя или аудитории требует подтверждения.
4. **Обмен занятиями.** В помощнике выбери подходящий вариант в секции «Обменять парами». Оба занятия перемещаются атомарно, после предварительной проверки каждой стороны; `Ctrl+Z` должен вернуть оба обратно.
5. **Объяснение запрета.** Попробуй перенести пару в красную ячейку; редактор не должен сохранять нарушение, а должен объяснить причину.
6. **Длинные таблицы.** В «Академических данных», «Нагрузке», «Аудиториях», «Отчётах» проверь поиск и выбор 12/24/48 строк на странице. Списки больше не должны удлинять страницу бесконечно.
7. **Большой выбор групп.** В редакторе нажми «Все поля» → «Группы-участники» → «Изменить»; откроется ограниченный по высоте список с поиском и небольшими чекбоксами.
8. **Горячие клавиши.** `Esc` закрывает режим подсветки переноса, `Ctrl+Z` отменяет последнее действие в основном редакторе. В полях ввода системная отмена набранного текста не перехватывается.

**Ограничения:** подсказки о квалификации основаны на демонстрационном справочнике, а не кадровых документах колледжа. «Проведённое занятие» запрещено менять через быстрые действия. Отмена последнего действия действует на операции основного редактора, а не на массовые операции других экранов. История изменений в браузере не заменяет серверный аудит и согласование опубликованных изменений.

Это обзорная функциональная проверка, не подтверждение реального журналирования, нормативного учёта преподавательской нагрузки, назначений TeachingAssignment или внешних интеграций.


## Обновление: интеллектуальное назначение, календарь и циклы

### Создание занятия за несколько действий

1. Открой «Расписание», выбери группу и пустую ячейку.
2. В форме «Новое занятие» выбери, с чего начинаешь: с группы или преподавателя.
3. Выбери известное учебное назначение из демонстрационных связей. Предмет и преподаватель подставятся автоматически.
4. Открой «Аудитория»: показываются только свободные и подходящие помещения с количеством мест и компьютеров. **Номер аудитории не нужно печатать вручную.**
5. Для практики с 28 студентами и 15 компьютерами выбери «Разделить» — система предложит две подгруппы и отдельные компьютерные кабинеты.
6. «Дополнительные параметры» по умолчанию скрыты. Ручное изменение учебных назначений — только демонстрационный режим, не эквивалент проверки TeachingAssignment.

### Учебный календарь

- Отражает **периоды учебного года**, а не еженедельные занятия: учебные недели, экзамены, практики, каникулы и нерабочие дни.
- На временной полосе выбери неделю: мини-расписание покажет существующие занятия, а проблемные периоды — число затронутых пар.
- При создании практики, каникул или выходного проверь список затронутых занятий. Сохранение календаря **не удаляет** их автоматически.
- Попробуй назначить обычное занятие на дату каникул: ручной редактор должен объяснить блокировку.
- Академические годы и учебные графики в реальной системе задаются централизованно в Academic Core.

### Шаблоны — повторяющийся цикл на несколько недель

1. Выбери группу и **неделю-образец** с уже настроенными занятиями.
2. Укажи длительность цикла: 1, 2 (А/Б), 3 или 4 недели.
3. Выбери **начальную и конечную** неделю, на которые распространить образец. В стенде доступно 16 недель (это не полный учебный год).
4. Укажи, заменять ли обычные занятия целевого периода.
5. Нажми **«Рассчитать изменения»** и сравни две мини-сетки **«Сейчас»** и **«После применения»**. Под ней показаны пропущенные занятия и причины, затронутые недели и влияние учебного календаря.
6. Подтверди результат. Общие потоки и параллели не разбиваются автоматически на независимые записи группы.

### Автосоставление — режим предварительного просмотра

1. Выбери группу и существующее демоназначение (предмет и преподаватель связаны).
2. Укажи число занятий, дни и крайний номер пары.
3. Нажми **«Показать предложенный вариант»**.
4. Посмотри мини-сетку и нагрузку по дням; новые занятия подсвечиваются.
5. Подтверди **«Добавить … занятий в черновик»**. Пока предложение не принято, оно не меняет расписание.
6. Если компьютеров не хватает, система не создаёт опасное назначение в кабинете с 15 ПК для 28 студентов. Сначала настрой подгруппы.

Важное ограничение: прототип автосоставления не учитывает все трудовые нормы, ставки, траектории студентов, учебные планы, последовательность дисциплин, межкорпусные переходы и реальные TeachingAssignment. Нельзя считать его готовым автоматическим расписанием для колледжа.

### Визуальный контекст на других экранах

Открой «Аудитории», «Замены», «Нагрузка», «Группы», «Студент», «Преподаватель» и другие разделы — наверху показаны недельная мини-сетка и загрузка по дням. Кнопка **«Свернуть»** убирает их для работы с таблицами. Длинные списки остаются постраничными.

### Следующие инновации (идеи, ещё не реализованы)

- Режим «что, если»: пакет переносов в отдельном сценарии с общим сравнением до применения.
- Предиктивное выявление проблем: предупреждение о перегрузке корпуса/преподавателя до публикации.
- Ремонт расписания одним действием: предложить 3–5 перестановок при закрытии кабинета.
- Согласование изменений с методистом и заведующим отделением, версиями и аудиторским следом.
- Оптимизация последовательности занятий по корпусам, окнам, оборудованию и доступности преподавателей.


## Электронный календарный учебный график (КУГ): первая функциональная версия

На экране «Учебный календарь» теперь сначала показывается матрица академического года (сентябрь — август, включая неполные календарные недели). Можно фильтровать отделение/курс/группы, выбирать несколько групп флажками, выделять недели с Shift или мышью, выбирать тип периода и просматривать результат перед сохранением. Отдельный режим показывает год одной группы. Проверка отмечает незаполненные дни и смешанные недели. Праздники показываются дополнительным слоем и не изменяют основной тип периода. Старый редактор и федеральный производственный календарь сохранены в раскрываемом разделе.

**Данные:** использован существующий локальный массив CalendarEvent с опциональным periodCode (различение учебной/производственной/преддипломной практики, аттестации и др.). Общие периоды остаются базовыми; новые групповые интервалы переопределяют их только для целевой группы. При изменении пересекающихся интервалов группа не теряет непересекающиеся части. Изменения сохраняются в том же localStorage, принудительного сброса нет.

**Импорт/экспорт:** кнопка CSV для Excel экспортирует недельную таблицу; неоднородные недели используют семь отдельных кодов дней, поэтому импорт собственного структурированного CSV восстанавливает точные даты. Импорт проверяет год, группы, заголовок и коды, сначала показывает количество изменяемых групп и интервалов. JSON выгружается для резервного копирования, но автоматическое восстановление JSON пока не реализовано. Отдельный сценарий копирует годовой график группы с возможностью сохранения или явного замещения уже заполненных периодов. Импорт XLSX без CSV-конвертации пока не реализован.

**Ограничения:** этот прототип не подключён к реальному Academic Core. Основной демонстрационный механизм Lesson всё ещё использует относительные недели с датой начала 09.11.2026 и собственный ограниченный горизонт годового решателя. Полная миграция на учебный год с сентября, серверный аудит, утверждение, нормативная сверка часов, полноценный импорт XLSX и адаптивные визуальные тесты требуют отдельных проверенных изменений. Нельзя считать эти функции работающими только потому, что матрица охватывает весь учебный год.
